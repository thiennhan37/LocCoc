# ADR-020: One Python AI runtime

Accepted 2026-11-17. Supersedes the separate enhancement runtime in ADR-015/017.

Move the Nest image enhancement implementation into `ai-service/app/enhancement`.
Keep `/ai/images/enhance`, multipart `image` + `filterId`, fixed diary/sticker
prompts, binary responses, input/output validation, cancellation and safe errors.
Embedding/search stay in their existing modules; Java Post remains the media
authority. Enhancement does not persist images or modify the vector index.

Both capabilities use Python port 8087, independent feature flags and provider
keys. Enhancement can run without Qdrant/semantic readiness. Redis enforces
independent enhancement budget counters; zero configured budgets fail closed.
All enhancement calls require a trusted service token, injected by Nest Gateway
only for the fixed enhancement route after stripping caller credentials. Internal
embedding endpoints still require their additional operation/owner capability.
Gateway never forwards internal paths to Python. Existing gateway image rate
limits and streaming remain. Spring Gateway parity is a separate task.

Bound the entire multipart request (including overhead), decoded image pixels,
file size and generated bytes. Timeout covers upload and processing, and client
disconnect cancels the provider coroutine. Gemini automatic retries are disabled;
ambiguous billable requests do not refund budget reservations. Provider replies
must be inline image bytes; no output URL is fetched. Sticker PNG must contain
at least one transparent pixel.

Retire Node runtime only after Python contract tests and Gateway streaming tests
pass. Preserve original prompt text and Git attribution to NhanTr. Do not migrate
or print local secrets; operators point Gateway AI_SERVICE_URL to 8087, configure
AI_SERVICE_TOKEN and explicitly enable enhancement/budgets.
