# Unified Gemini moment-search implementation report

Date: 2026-11-14. Scope: smart moments and its AI/Gateway/Flutter integration,
not an audit or production deployment of the whole monorepo.

## Delivered runtime

- Unified Python source in `ai-service`. Removed the complete former
  `ai-service-2` directory, local-provider/download code and obsolete virtualenv.
  No local model weights remained in that directory. Existing `ai-service/.env`
  and unrelated ignored Node build artifacts were not overwritten.
- Gemini Embedding 2 through official async SDK, 768-dimensional finite normalized
  vectors, CPU image with pinned Python digest/dependencies, async Qdrant with a
  dedicated profile/collection, schema/index validation and scoped point IDs.
- Service token plus short-lived signed operation/owner/asset capabilities; no
  public AI APIs, user-supplied owner/filter/vector, arbitrary URL fetch or raw
  provider/vector/payload response. Bounded upload/decode/query/cache/concurrency.
- Separate NestJS MomentService: JWT + live account authority, independent
  PostgreSQL metadata, private S3 processed images, transactional job/outbox,
  SKIP LOCKED leases and per-moment advisory locks, CAS completion, SHA-256 source
  validation, retries/failures/Retry-After, deletion/staging/account-event cleanup.
- Hybrid retrieval + final authoritative owner/state/version/date/place/album
  checks. Vietnamese calendar parsing uses UTC+7. Explicit metadata-only fallback
  is distinct from semantic success; required-semantic and authority failures
  cannot become empty success.
- Both gateways route `/moments`, preserve raw image bodies and enforce limits;
  `/ai` is closed. Flutter opt-in has gallery/upload/search, date/place filters,
  pending/failed/retry/fallback, current-session fences for JSON and private images,
  lazy image fetch, bounded in-memory image futures and status polling that keeps
  loaded gallery pages. Photos are authenticated read-through, not public URLs.

ADR-016 records the intentional differences from the original ADR-015 plan:
PostgreSQL job polling worker colocated with MomentService instead of Kafka
index-job delivery/AI callbacks; authenticated image reads instead of presigned
URLs. Existing Kafka account-deletion events remain integrated. Metadata is
immutable after upload in this MVP; metadata editing and album management/sharing
are not exposed.

The initial smoke used the pre-existing legacy key under a mistaken assumption
that it was intended for this test. The user clarified it is paid and prohibited
its use. A distinct embedding-only field was added without changing the old value.
Runtime, smoke and configuration helpers now exclusively use the dedicated field;
tests prove legacy `GEMINI_API_KEY`/`GOOGLE_API_KEY` cannot act as fallback. The
container was rebuilt with the corrected code. No keys/vectors were printed.

Total Gemini requests during this task: **6**, split **2 legacy / 4 dedicated**.
No personal photos were sent. Both image/text vectors were 768-dimensional and
valid; the synthetic-pair cosine was 0.7105. This is transport/shape evidence,
not retrieval quality, billing, free-tier entitlement or p95/p99 evidence. Actual
billing amount is unknown. No additional live requests are scheduled.

The isolated runner creates unique disposable containers on random loopback ports,
uses generated process-only credentials/synthetic images and removes only its own
containers. Existing databases, collections, buckets and root/service secrets were
not reset. One expanded-run failure exposed competing automatic/manual test-worker
execution; tests now explicitly control the worker in NODE_ENV=test. Startup also
bootstraps the collection, with honest unready recovery during dependency outages.
The subsequent full isolated run passed.

Flutter initially could not compile because an already-imported
`account_security.dart` was missing in the checkout. Its strict session replacement
model was supplied and existing security tests passed. The global `**/models/`
ignore was narrowed to AI model paths so future Dart domain models are not ignored.
Minor analyzer findings (unused imports/callback arguments/braces) were fixed.

## Activation and remaining acceptance

Local activation was explicitly authorized and executed. The configure helper's
`--apply` path successfully created the independent `moments` DB/role, applied its
migration, created `loccoc-moments-private`, saved distinct internal service
credentials in ignored service `.env` files and enabled the flags. Existing
provider/Auth/storage keys and unrelated business records were preserved.

AuthService :8000, Nest Gateway :8080, AI :8087 and MomentService :8088 were started
as hidden background processes; existing UserService :8081 was preserved. Gateway,
AI liveness/readiness and Moment liveness returned HTTP 200 after testing.

`verify-moments-local-live.mjs --live` passed eight checks against the actual local
deployment and real Gemini: two synthetic Auth/JWT accounts, unauthenticated/
owner-field rejection, private upload + durable pending/ready index, second-tenant
read/delete rejection, Vietnamese vector retrieval (caption deliberately does not
match the query), authenticated image read, immediate deletion and completed
external cleanup. Exactly two new requests were reserved and both succeeded; no
retry. Synthetic accounts were tombstoned via real account authority, without
sending email. Raw evidence (no keys/tokens/photos):
`logs/moments-local/live-verification-3118381f-38b4-4993-9db0-b9a6c7fb0981.json`.

Android debug APK successfully built with `MOMENTS_ENABLED=true` at
`MobileApp/build/app/outputs/flutter-apk/app-debug.apk`. No physical-device install/
interaction was performed. Existing Firebase emits a future Kotlin migration
advisory; current build succeeds. Current dev storage uses existing local storage
credentials; this is not a claim of production bucket-scoped IAM isolation.

Production remains No-Go until private-data/provider conditions, scoped credentials/
TLS, representative retrieval/no-answer quality, 10k/100k/C=20 live load, cost/quota,
freshness/restore/reindex/reconciliation and operational monitoring gates pass.
No benchmark or production SLO has been fabricated from mock/local-Qdrant results.
